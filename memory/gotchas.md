## 데이터·자산

### `_demo/*/..._demo_format.mp4`가 심볼릭 링크일 수 있다
PiP에 점군 데모 대신 **raw 촬영 원본이 나오면** 먼저 `readlink`를 하라.
`upload_1781521406685`의 경우 실파일이 아니라 `out_kakao_fmt/KakaoTalk_...mp4`를 가리키는 심링크였고
타깃이 삭제돼 있었다(폴더가 비어 있었음). `ls -la`에서 **크기 100바이트**로 보이는데, 그건 스텁이 아니라
**링크 경로 문자열 길이**다. 이걸 스텁으로 오독해서 한 번 헛짚었다.
→ 깨진 링크를 지우지 않고 렌더를 돌리면 ffmpeg가 링크를 따라가 **결과물이 엉뚱한 폴더에 쓰인다**.

### 워크트리에는 gitignore된 픽스처가 없다 → 핵심 테스트가 조용히 skip된다
`git worktree`로 작업할 때 `models/Gasan_7F`, `realtime/_uploads`가 없어서
`test_build_coplay_rigid` 등 **기하 테스트 17건이 skip**되고 `test_anchors`/`test_pipe_path`는 수집 에러였다.
"게이트 통과"가 실제로는 핵심 검증을 건너뛴 통과였던 것.
→ 워크트리 생성 후 본체로 심링크할 것(둘 다 .gitignore 대상이라 커밋 오염 없음):
```bash
ln -sfn <repo>/models/Gasan_7F models/Gasan_7F
ln -sfn <repo>/realtime/_uploads realtime/_uploads
```
확인: `pytest tests/ -q`가 **0 skipped**여야 한다.

### 이 업로드(`upload_1781521406685`)에는 문이 물리적으로 없다
문 검출기 2종(점군·영상)을 만들어 돌렸으나 **수용 0건**. 아슬아슬한 0이 아니라 **증거 부재형** 0이다:
RGB 42후보 전원 shape ≤ 0.002 vs 합성 진짜 문 0.922~0.939, 막다른길조차 0.910 — 자릿수가 다르다.
프레임 육안 확인 결과 개방형 오피스(유리 파티션·목재 기둥·천장 노출 배관)이고 문틀 통과 장면이 없다.
또한 **카메라가 천장을 향한다** — 중력정렬 프레임에서 점군의 **82%가 카메라보다 위, 51%가 1m 이상 위**.
배관 커버리지 목적 촬영이라 정상이지만, 평면매칭이 필요로 하는 벽·문 증거는 담기지 않는다.
→ 이 한 가지가 여러 난항을 동시에 설명한다: 점군 문검출 5.1배 불일치, RGB 0건,
저변경 구간에도 남는 모호성, s_h(1.97) vs s_f(3.53) 1.8배 차이.
→ **향후 촬영에서 평면매칭을 쓰려면 카메라를 수평으로 들거나 벽을 훑어야 한다.**

## 측정·게이트

### 게이트가 통과 불가능한지 먼저 확인하라 — 오라클 실험
매처를 18사이클 고쳤는데 게이트 90%에 한 번도 못 닿았다. 물었어야 할 질문:
**"매처에게 정답을 그냥 건네주면 통과하는가?"**
→ legacy 설정에서 **4/20 = 20.0%**. 정답을 줘도 20%인 시험이 90%를 요구하고 있었다.
케이스 #19가 산수 증명: 생존 plan event 7개를 **전부** 맞춰도 7/12 = 0.583 < 0.60 → reject.
→ 지금은 `compute_oracle_upper_bound()`가 **모든 게이트 출력에 상한을 함께 표시**한다. 같은 혼동 재발 방지.

### recall 같은 커버리지 지표는 범람으로 통과된다
outlier recall을 38.8% → 91.2%로 올린 직후 개발 역할이 자진 신고:
**span을 전부 깃발 꽂으면 recall 100%**. 실측으로 확인 — flood 구현에서 recall이 오히려 **98.75%로 상승**했다.
→ 정밀도 지표를 짝지어야 한다. flood는 수학적으로 `precision == prevalence`이므로
그 항등식을 넘는지가 검정 기준이 된다(`--selftest-flood`가 이걸 회귀로 고정).
→ **임계를 현재 값에 맞춰 역산하지 말 것.** prevalence는 매 실행 ground truth로 재계산한다.

### `| tail`이 파이프라인 종료코드를 가린다
`bash render_demo_format.sh ... | tail -30`으로 실행했더니 3단계(합성)가 실패했는데 **exit 0**으로 보고됐다
(`tail`의 상태가 파이프라인 상태가 됨). 스크립트 안에 `set -euo pipefail`이 있어도 소용없다 — 그건 스크립트 내부용.
→ 긴 스크립트는 출력을 파일로 받고 종료코드를 따로 확인하라.

### 서브에이전트 측정과 구현을 같은 파일 위에서 동시에 돌리지 마라
QA가 "sweep 재현성 결함(같은 시드인데 실행마다 값이 다름)"을 보고했는데, 인용 수치가
dev의 A/B 결과와 정확히 일치했다 — **dev가 그 파일을 편집하는 동안 QA가 측정해 편집 전/후를 잰 것**이다.
커밋 후 2회 실행하니 완전 동일했다(유령 버그).
→ **소유 분리는 '쓰기' 충돌만 막는다.** 측정은 런타임에 남의 파일을 읽으므로 격리되지 않는다.

## 도구·설정

### 바인딩 모드를 바꾸면 어떤 설정이 이기는지가 바뀐다
헤드리스(`claude -p`)에서는 CLI `--max-turns`가 이기지만, 인세션에서는 **정의 파일 frontmatter가 이긴다**.
config만 60으로 올리고 `.claude/agents/*.md`를 30으로 두었더니 전환 직후 조용히 옛 한도로 돌아갔고,
서브에이전트가 116k 토큰을 쓰고 **디스크 산출물 0**으로 끝났다.
→ 양쪽을 함께 갱신하고, **워크트리 사본까지 동기화**할 것(인세션 스폰은 워크트리 정의를 읽는다).

### 긴 측정을 먼저 돌리면 산출물이 0이 된다
서브에이전트가 측정만 하다 턴이 끝나 파일을 못 쓰는 일이 3회 반복됐다(한 번은 141k 토큰 소모).
→ **"코드/문서를 먼저 저장하고, 측정할 때마다 갱신하라"**로 순서를 뒤집으면 해결된다.
턴이 끊겨도 그 시점까지가 디스크에 남는다.
